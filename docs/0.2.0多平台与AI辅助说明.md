# 0.2.0 多平台与 AI 辅助

本次从 TikTok 主平台升级为 TikTok、Instagram、YouTube 三个平台可分别创建批次。使用方式和原来一致：选择平台 → 粘贴一批主页 → 开始读取 → 复制结果 → 下一批。每批只属于一个搜索平台。

## 界面与输出

- 原「达人采集」「历史记录」页标题位置改为三个平台的图标切换；顶部操作台／历史记录导航保留。历史按平台显示，读取历史不访问网站。
- 切换平台时保存已读批次和各平台草稿，运行中先暂停。输入校验、示例、批量粘贴、主页列名和粉丝量／订阅数列随平台切换。
- 每个平台输出 14 个可配置业务字段：主平台主页 URL、联系方式、博主 ID、性别、博主名称、主平台粉丝量／订阅数、中位播放数、平均播放数、量级、其他两个平台各自的主页 URL 和粉丝量／订阅数、达人类型。行尾关键词和读取状态不复制，品牌视频链接仍只在详情展示。
- 跨平台账号只采用博主明确提供的主页链接、绑定账号或用户手动填写。没有找到就空白，不按姓名搜索，也不猜测同名账号。其他平台未授权、失败或未公开数量，不影响主平台完成状态。
- 旧历史按原快照查看；已有列顺序和手动修改保留。新字段补充到可配置列中；不把历史缺失信息伪造成新数据。
- 拖动列时停在抽屉内容区的上下边缘会持续自动滚动，停止拖动或关闭抽屉后停止。原有上下移动按钮仍可使用。

## 统计口径

TikTok 保持已有口径和采集通道。YouTube 同时读取普通视频及 Shorts，再按发布时间合并、去重、计算；不统计直播和直播回放。Instagram 的图片／轮播作品可参与品牌关键词检索，公开播放统计仅计视频，缺失播放不当作零。

无品牌词时只确认用户设定的天数／条数；有品牌词时另覆盖近 180 天，视频数不限。分页有时间边界校验；YouTube 两个列表都需证明覆盖，不能只读到普通视频便输出合并的完成均值。日期、播放量、游标缺失或作者不匹配均保留原因，不把空响应当作读取完成。YouTube 若只公开日期，明细保留 `datePrecision: day`，不伪造具体发布时分秒。平均值是样本作品当前累计播放数的平均，不是统计期间新增播放。

## 读取机制与已知限制

YouTube 读取频道页的原生列表数据，通过网页 browse continuation 翻页，读取作品公开详情以取得发布时间和播放数，兼容 videoRenderer、lockupViewModel 和 Shorts 结构。该流程在现有授权浏览器中后台请求，不滚动或刷新用户页面。

Instagram 优先读取主页内嵌的 JSON／GraphQL 资料，支持 `xig_user_by_username` 和 `polaris_ordered_timeline_connection`；缺失作品信息时读取公开作品详情。旧主页接口和用户 feed 为兼容通道。主页导航初期捕获内嵌数据，必要时只初始化一次插件自有后台标签页；不导航用户标签页。登录、验证、403、429会明确暂停或记录，不尝试绕过。

实测发现新 YouTube 页面已改用 lockupViewModel，旧解析只读 videoRenderer 会看到游标但读不到作品。另在真实 YouTube 页面，站点 Trusted Types/CSP 会阻止内联脚本或页面世界的字符串解析；新读取组件采用扩展的 ISOLATED 注入。Instagram 开源项目已说明旧 web_profile_info 接口可能返回 400／401／429；另外 API 404 不能证明账号不存在。上述情况均有独立处理。

### 本轮验证边界

- 2026-11-26，以独立、未登录的 Chrome 实际读取 `https://www.youtube.com/@mkbhd`：取得频道名称、公开订阅数、普通视频和 Shorts，完成最近 1 条视频的统计。数值随采集时点变化，详见开发目录 `artifacts/revision-0.2.0/live-platform-research.json`。
- Instagram 匿名实测被要求登录；本轮没有取得用户已登录会话，不能宣称已完成真实登录环境的批量验收。内嵌 JSON、feed 分页、图片排除、跨平台串号拒绝及登录暂停恢复均通过独立浏览器模拟测试。
- AI 使用可控的兼容接口模拟响应验证文本、多图（含缩图转码）请求与错误处理；未调用用户真实服务，也未测量真实模型的分类准确率。

## 可选 AI

首页右侧「任务设置」中的「AI 辅助」打开设置。填写 OpenAI Chat Completions 兼容的接口地址（通常以 `/v1` 结尾，亦可填写完整 `/chat/completions`）、模型名称、API Key，按「保存并测试」验证。默认关闭；没有接入仍用本地标签／描述规则。

开启后，当前已读批次与后续完成基础读取的达人会异步分析。提交简介和当前播放统计范围内最多 40 条均匀抽样的视频标题／描述／hashtag；采集本身没有这个数量上限。用户勾选「结合多条视频封面／缩略图」时，还会在这些样本中均匀抽取最多 6 张主页视频封面／缩略图，缩至最长边 640px 后与文字一同发送。图片只用于判断主题，不用于性别；它们不是播放后的实际视频截图。勾选图片时须选择支持图片的模型，「保存并测试」会实际发送一张测试图片验证兼容性。不发送录入的联系方式、登录凭据、头像或视频本体。模型响应必须引用实际样本视频 ID，证据不足保留本地分类；人工修改优先于模型。

性别只接受本人明确自述，或用户人工填写。AI 可以提取简介原句，但程序会复核原句确实存在并通过自述解析；不会根据名字、头像、声音、视频人物或明星推断账号所有人的性别。因此开启 AI 后性别仍可能为空，这符合证据不足时留空的要求。

Key 只存当前 Chrome 用户的扩展本地存储，与任务快照分开；不会返回给普通 GET、复制诊断或打入 ZIP。临时图片仅在内存处理，不放入历史结果、诊断和分发包。图片未授权、失效或超时会说明实际取得的张数，零张时使用文字补充；模型拒绝图片则保留本地结果。API 地址变更不会把旧密钥发到新地址；地址和模型需由用户确认填写。按具体接口域名及用户选择的公开图片CDN域名单独请求浏览器权限，不会因打开设置就访问全部网站。接口超时、错误 JSON、HTTP 401／429／503 等只影响 AI 补充，基础资料和本地分类继续可用。

更好的类型覆盖不等于已验证的准确率。建议日后选取运动、美食、科技、明星粉丝号、团队号和混合内容等人工标注样本，比对接入前后的正确率及留空率，再决定模型和提示词。

## 更新

解压新版 ZIP，运行「安装或更新.cmd」，回到原工作台点击「应用更新」。沿用原固定目录和插件身份，不卸载。AI 默认不启用，需要时再配置；其他电脑需各自安装、登录、授权和填写自己的 AI 配置。
